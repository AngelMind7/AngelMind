# AngelMind Threat-Model Register

**Status:** Repository security register  
**Scope:** Control plane, worker, storage boundary, authentication boundary, and passive-only research workflow  
**Last reviewed:** 2026-09-02  
**Owner:** Security and platform maintainers

## Purpose and security posture

Register ini adalah catatan risiko yang dapat diaudit untuk implementasi repository AngelMind. Register ini tidak memberi izin untuk melakukan probing, exploitation, credential testing, fuzzing, atau tindakan target-facing. Semua workflow riset harus tetap berada pada passive-only boundary; adapter, capability, atau model recommendation bukan otorisasi eksekusi.

> Risiko dinilai pada jalur repository. Ketersediaan credential provider, deployment hardening, database backup, domain configuration, dan smoke test live tetap menjadi tanggung jawab environment owner.

## Rating method

Likelihood dan impact memakai skala **Low**, **Medium**, dan **High**. Severity adalah keputusan gabungan yang mempertimbangkan exposure, exploitability, blast radius, dan kemampuan deteksi. Status **Open** berarti residual risk masih memerlukan keputusan atau verifikasi; status **Mitigated** berarti kontrol repository tersedia tetapi tetap membutuhkan monitoring.

## Required review triggers

Register ini harus ditinjau ketika ada perubahan pada authentication, authorization, storage, worker handlers, model/provider routing, external notification, migration schema, runtime binaries, or any capability that could cross the passive-only boundary. Review juga wajib dilakukan setelah incident, failed restore drill, confirmed dependency vulnerability, atau perubahan data-retention policy.

## Evidence standard

Setiap perubahan status harus merujuk pada commit, test output, migration identifier, atau verified environment record. Dokumentasi tidak boleh menyatakan threat telah selesai hanya karena ada folder, route shell, konfigurasi contoh, atau tombol UI. Untuk kontrol yang bergantung pada deployment, status repository tetap **Mitigated** atau **Open—deployment control** sampai bukti live tersedia.

## Security decisions that remain intentionally deferred

Break-glass privilege, SSO/SCIM provider provisioning, MFA/passkey enforcement, external malware provider, provider-level AI routing, target-facing adapters, production restore, dan DAST tidak diaktifkan hanya untuk mengubah status register. Masing-masing memerlukan owner, scope, approval, secret handling, rollback, dan verifiable evidence terpisah.
