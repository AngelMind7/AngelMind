# Localization and RTL

AngelMind uses a global locale provider with persistent language selection, English fallback, locale-aware date and number formatters, and twelve enabled interface locales: Bahasa Indonesia, English, Bahasa Melayu, Arabic, Simplified Chinese, Japanese, Korean, Spanish, Portuguese, French, German, and Russian. The language selector is available in both the desktop sidebar and compact mobile header. A `lang` query parameter is supported for deterministic locale preview, such as `?lang=ar`.

The Arabic preview confirms translated navigation, native language selection, and RTL typography. The review also identified that the generic sidebar/inset geometry needs an explicit RTL placement override to prevent the first assurance card from approaching the left navigation boundary. That correction is tracked before release; workflow data and governance behavior remain locale-neutral.

The corrected RTL preview places the desktop navigation on the right, preserves the workspace content inset, and keeps the mobile header, navigation trigger, language selector, form controls, and assurance cards legible. English operational copy remains the deliberate fallback for messages that do not yet have a locale-catalog key; policy data, evidence, audit values, and operator-entered text are never machine-translated or modified by the interface.

The final dual-locale deep-link capture encountered the authenticated application loading skeleton before page content settled. This is treated as an inconclusive screenshot, not a visual approval. The type-checked catalog contract verifies the locale data; a subsequent settled browser review is required before release.

A subsequent settled review confirmed Indonesian translations for the command hierarchy, Assurance page title and description, reviewer and incident headings, form placeholders, and the shared navigation. The Arabic review retained right-side sidebar geometry, RTL readable descriptions, and Arabic placeholders. Technical strings that must remain exact—such as `HTTPS`, `SHA-256`, and webhook labels—remain in English by design. Any static phrase absent from the translation catalog falls back to English rather than silently altering governance, evidence, or user-entered data.

The generated static catalog is curated before use. Entries that resemble source code, implementation syntax, tooling labels, or invalid phrasing are rejected by the curation script and the runtime phrase guard. The localization inventory covers the nine authenticated routes: command center, workspaces, governance, findings, audit, observability, notifications, operations console, and assurance control. Shared navigation, static interface copy, and browser-formatted date/number output participate in the selected locale; source-entered program data and credentials remain untouched.

The command center now uses an explicit typed locale resource for its primary headings, metrics, rehearsal guardrails, coverage panel, and activity empty state across all 12 supported locales. Pages that render audit, approval, incident, notification, archive, workspace, or operations timestamps use the `LocalizedDate` component and the locale provider's formatter. A regression suite rejects direct browser-default timestamp rendering in those page components.

Assurance Control and Signal Center now also use an explicit typed resource for their controlled headings, descriptions, action labels, placeholders, empty states, and notification-preference definitions. Workspace names, incident titles and descriptions, audit payloads, SHA-256 values, URLs, and other operator-entered or governed records remain unmodified. Native-language title corrections are applied for Arabic, Japanese, Korean, and German where the initial translation pass retained an English display label.

Users can choose a persistent IANA timezone alongside language in both the sidebar and mobile header. Timestamps remain stored as UTC values and are only formatted for display through the selected locale and timezone. The authenticated route map now loads all nine dashboard pages lazily behind an accessible loading state. Automated coverage verifies the locale-copy completeness, timezone validation and formatting, absence of browser-default timestamp formatting, and the lazy route boundary.

The final locale pass also places all Signal Center event-preference titles and explanations, as well as Assurance severity labels and escalation timing labels, behind explicit translation keys for each supported locale. The legacy static text fallback receives the same selected IANA timezone as the explicit timestamp component, so legacy browser-formatted timestamps cannot silently ignore the display preference. Regression tests reject the former hardcoded workflow labels and verify the timezone-aware fallback.
